# rules_osv

Bazel rules for osv-scanner, offline:
- `osv_scan_test`: lockfiles vs a pinned OSV database snapshot; findings fail unless an ignore entry (id, reason, expiry) covers them, and expired entries fail;
- `osv_db`: one ecosystem's database (pinned snapshot, mirror zip, or OSV JSON records).

See DESIGN.md.

## Commit requirements

- All tests must pass before any commit with code changes: `bazel test //tests/...` and `.github/consumer/check.sh <scratch dir>` (it archives HEAD, so commit first and amend if it fails).
- All documentation (`README.md`, `DESIGN.md`, `CLAUDE.md`) must be updated to reflect any code changes before committing: new rules, changed attributes, new public API surface, behaviour changes.
- Never commit `bazel-*`, `MODULE.bazel.lock` or `__pycache__` (`.gitignore`). The MODULE.bazel.lock test fixture is generated by a genrule from `tests/testdata/unsupported/bzlmod/module_bazel_lock.json`.
- Never commit the snapshot zips. They are release assets (`tools/snapshot_db.sh` prints the upload command); the repository pins only their shas.

## Key concepts

- **Offline layout.** osv-scanner v2 reads `<--local-db-path>/osv-scalibr/<Ecosystem>/all.zip`, one per ecosystem of the scanned packages. A missing one is exit 127, which the driver turns into "`db` has no <Eco> database".
- **Nothing implicit.**
  - Flags: `--offline` (= `--offline-vulnerabilities --no-resolve`), `--no-call-analysis=all`, and an empty `--config`, so no `osv-scanner.toml` is picked up.
  - Environment: `OSV_SCANNER_*` / `OSV_SCALIBR_*` removed, and `HOME` set to a temp dir.
  - The `block-network` tag is always added by the `osv_scan_test` macro.
- **Ignores are applied by the driver**, as osv-scanner's `filterPackageVulns` does: a group is ignored when any ID or alias matches. The driver does it, rather than osv-scanner, so that it can fail on expired entries and note unused ones. A date expires at 00:00 UTC that day.
- **Exit codes (driver).** 0 clean; 1 findings or expired entries; 2 a malformed ignore file, a missing database, an unreadable lockfile, or osv-scanner failing.
- **Snapshot hosting.** Release assets `db-<date>/<Eco>-all.zip`. Hub `@osv_db` has one `osv_db` per ecosystem; each zip is a separate lazily fetched repo. `--distdir=<zips dir>` serves them before the release exists.
- **Toolchain.** Unversioned `osv_scanner_<plat>` repos; keep `DEFAULT_VERSION` and `osv.version()` in `MODULE.bazel` equal (`//tests:version_test`, which also runs `osv-scanner --version`).

## Public API

```python
load("@rules_osv//:defs.bzl",
    "osv_scan_test",   # lockfiles, db (osv_db targets, one per ecosystem), ignore, env
    "osv_db",          # ecosystem, snapshot, zip | advisories, sha256 (display)
    "OsvDbInfo", "OsvScannerInfo",
)
# MODULE.bazel
osv = use_extension("@rules_osv//:extensions.bzl", "osv")
osv.version(version = "2.7.1", sha256 = {})                      # root overrides
osv.db(name = "osv_db", date = "", ecosystems = [], url = "", sha256 = {})  # root overrides by name
use_repo(osv, "osv_db")
```

### Test results (last full run: 2026-11-16)

All 31 test targets in `//tests/...` pass on Linux x86_64 (osv-scanner 2.7.1, Bazel 9.3.2, Python 3.14). Other checks:
- **Real snapshot:** `//tests:snapshot_test` passes, with `--distdir` on the downloaded zips because the `db-2026-11-16` release didn't exist yet. It shows 17 findings, snapshot `2026-11-16` and each zip's sha.
- **Consumer:** `.github/consumer/check.sh` passes:
  - the archive has no `tests/` or `tools/`, and `@rules_osv//...` loads;
  - an untagged root resolves;
  - an unsupported version or date fails, naming the tag;
  - a `file://` mirror snapshot: vulnerable fails, clean and ignored pass, and npm and other platforms' binaries are never fetched;
  - a self-pinned osv-scanner 2.7.0 runs.
- **Offline:** every scan is `block-network`; `network_blocked_test` shows connections fail (DNS still answers via the host resolver socket). Without the tag, the same probe connects.
- **Pins:** `tools/update_versions.sh --check`: all four platforms match the published sums and the downloads. Snapshot zips pass `zipfile.testzip()`.
- **Python:** the driver parses as Python 3.8 syntax; the vendored tomli is exercised by `vendored_toml_test`. No Python older than 3.14 was available to run it on.
- **Not run:** darwin binaries (no macOS host); linux_arm64 (no arm64 host).

## Known limitations

- `python3` (3.8+) on the host.
- `MODULE.bazel.lock` and `go.sum` aren't read by osv-scanner 2.7.1.
- Expiry is only re-checked when the test runs: a cached pass survives an expiry (run it uncached in CI).
- Snapshot refresh is manual: run `tools/snapshot_db.sh`, then upload with `gh release create`.
